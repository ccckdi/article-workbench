# 文章工作台

AI 全栈开发考核起始工程 · v0.4.0

开发工具、AI 工具和实现方案自由选择。

## 业务背景

一个内容团队维护面向新成员的办事指南。作者和编辑共同更新文章，内容负责人审核并发布。团队需要保证发布内容经过审核，作者也希望了解文章发布后的阅读情况，持续改善内容。

作者想知道自己的文章有多少人看、哪些文章更受欢迎、读者从哪里来，以及文章修改后阅读表现有什么变化。编辑希望了解团队文章的整体表现，发现值得关注的内容。请在现有工作台上完成文章协作审核、阅读数据和读者画像功能。

工程已有登录、角色、文章编辑、发布、公开阅读和持久化能力。当前可以直接发布，保存已发布文章会改变公开内容，旧编辑会覆盖新修改。正式提交、审核、版本保护、冲突处理、操作追溯、阅读统计和读者画像由你完成。

可以调整工程结构、语言与框架，保留完整业务流程。使用公开资料和开源代码时注明来源及必要的许可证信息。

## 业务要求

- **R1 写作与提交**：作者可以保存草稿、正式提交、查看待审核与处理结果。草稿与正式提交应清楚区分。退回必须带有意见，作者可以修改后再次提交。作者和编辑应能辨认当前内容、处理进度和待处理事项。
- **R2 人工审核与权限**：审核人员可以查看提交内容并作出通过或退回决定；发布人员可以发布或取消发布。普通作者不得审核或发布。审核者与发布者可以是同一人。权限限制由服务端执行，审核时能够辨认本次提交的内容及相对上一已发布内容的主要变化；首次提交明确显示为首次发布。
- **R3 可信发布**：首次发布和后续更新都必须对应人工通过的内容。标题、正文和公开摘要不得泄露未审核修改。修改已发布文章时，原已发布内容继续可见，直到新内容获批并被授权发布，或文章被授权取消发布。不能悄然改变正在审核的内容，也不能把旧批准用于新修改。
- **R4 多人编辑**：作者与编辑可以先后编辑同一篇文章。两人基于旧内容保存时，不得静默覆盖已保存的工作。冲突发生后，应保留当前用户的输入，提供能够辨认相关版本和变化的信息，以及可理解、可继续操作的处理方式。无需实时协同、自动合并或完整 Git 功能。
- **R5 操作追溯**：从文章中可以查询关键修改、提交、审核、发布和取消发布记录，辨认操作者、时间、内容版本、结果和意见。普通作者不能伪造或修改记录。重复点击、请求重试以及审核、发布与修改同时发生时，结果应可解释，不产生重复生效或错误发布。
- **R6 工程交付**：提供实际运行的前后端、持久化数据和必要测试。交付说明包含启动、验证、部署和数据恢复方法。重启后能继续处理文章、查看阅读数据和读者画像。根据实际数据变更说明处理方式。
- **R7 文章阅读数据**：作者可以查看自己文章的阅读量、访客数和阅读趋势，按时间范围查看单篇文章或比较多篇文章的表现。文章详情中能够查看阅读深度，了解读者是否继续阅读；文章更新发布后，可以比较修改前后的阅读表现。公开页面产生的新访问应反映到统计中，数据更新时间清楚，重复上报不能重复计数。
- **R8 读者画像**：作者可以了解自己文章的读者主要来自哪些渠道、使用什么设备、分布在哪些地区，以及读者的回访情况，并结合这些信息查看阅读表现。支持按文章和时间范围查看，帮助作者判断内容吸引了哪些读者、不同读者的阅读习惯有什么差异。编辑和内容负责人可以查看团队文章的整体情况。画像以汇总信息展示，数据不足或无法判断的部分应清楚标明。

## 协作边界

| 角色 | 业务范围 |
| --- | --- |
| 作者 | 查看、编辑和提交自己的文章，包括编辑修改后的内容；查看自己文章的处理记录、阅读数据和读者画像 |
| 编辑 | 查看、编辑和提交团队文章；查看团队文章的处理记录、阅读数据和读者画像 |
| 审核人员 | 查看团队文章、提交内容和处理记录；通过或退回提交 |
| 发布人员 | 查看团队文章、批准依据和处理记录；发布或取消发布 |
| 内容负责人（manager） | 具备编辑、审核、发布权限；查看团队阅读数据和读者画像 |
| 未登录读者 | 阅读已发布文章；不得访问非公开文章或作者后台的阅读数据 |

作者只能查看自己文章的数据，单独具有审核或发布角色的账号不具备阅读分析权限。服务端须执行同样的访问范围，不能通过修改文章 ID 或查询条件查看他人的数据。读者画像不展示可识别个人身份的资料；地区或设备无法获取时可以显示为未知。

取消发布不会自动抹去原批准依据；内容及批准仍有效时，可由发布人员再次发布。内容发生变化时，修改后的内容必须重新审核。文章在送审后如何继续编辑、如何认定提交失效以及如何处理冲突，由你设计并保持交互与服务端行为一致。

文章下线或更新不能抹去过去的阅读记录，也不能将旧版本的访问错误归到新版本。页面打开后再发生更新或下线时，迟到上报如何处理由你设计。统计口径、回访判断和阅读深度的呈现方式由你选择，并在交付说明中说明。

本题内容范围为普通文章的标题、正文和摘要，以及阅读数据与读者画像。不要求新增分类、标签、附件、评论、定时发布、外部审批或多级流程。

## 业务场景

文章 A 已发布，作者将其修改成 B。B 保存、提交、退回修改和重新审核期间，读者继续看到 A；B 获批并被授权发布后，读者才看到 B。审核人员能够确认自己处理的是哪份内容。另一位编辑从旧页面保存时，不能覆盖已保存的修改。

作者发布了一篇指南，想知道最近一周的阅读情况。她发现来自搜索的读者多，但手机访问的阅读深度偏低，便查看相关文章和时间段的数据，再决定是否调整内容。修改经过审核发布后，她可以继续观察前后的表现。编辑则可以切换到团队视角，比较不同作者和文章的阅读情况。

## 数据资料

`fixtures/article-analytics/` 提供两位作者的 8 篇历史文章及两个批次的阅读记录，包含来源渠道、设备、粗粒度地区和阅读行为，均为合成数据。资料可用于展示历史趋势、回访和不同读者的阅读情况；接入方式自行选择，不要求开发独立的数据导入管理页面。

数据字典与原始文件放在工程内。历史记录覆盖北京时间 2026-08-01 至 2026-08-14，既有批次重叠，也有缺失或不可靠的上报。演示时应同时能看到历史数据和新产生的访问，统计范围与更新时间清楚。历史快照用于分析，不代表本系统的审核批准；将历史文章用于新的公开演示时，应经过本题的审核发布流程。

分别以作者和编辑身份演示阅读概览、单篇详情、文章比较、时间筛选与读者画像。打开公开文章产生新访问，核对统计变化；展示文章更新前后及下线后的历史数据。结合页面说明观察到了什么、哪些情况还无法判断，并核对一项指标的实际数据。

## 启动

准备 JDK 21、Node.js 24（至少 24.11.0，含 Corepack）。在项目目录执行：

```sh
cd ui
corepack pnpm install --frozen-lockfile
corepack pnpm build
cd ..
./gradlew :backend:bootRun
```

访问 http://localhost:8090 ，工作台为 http://localhost:8090/console/ 。初次启动自动初始化演示数据。Windows 使用 `gradlew.bat`。

首次安装会下载构建工具和依赖，无需另外安装数据库或获取其他业务工程。

```sh

```

通过 http://localhost:3000/console/ 访问支持热更新的工作台，公开阅读仍访问后端 8090 端口。改变后端端口时，给前端设置 `API_PORT` 和 `VITE_PUBLIC_ORIGIN`。

打包产物为 `backend/build/libs/article-workbench.jar`，包含后端、工作台静态资源及公开阅读模板。在项目目录执行：

```sh
java -jar backend/build/libs/article-workbench.jar
```

运行产物只需要 Java 21。按 Ctrl+C 停止，重新运行上述命令即可恢复服务。

## 数据与配置

默认数据目录为运行目录下的 `data`，使用 H2 文件数据库。开发启动与在项目目录运行 JAR 时使用同一数据目录。账号、文章在重启后保留，会话失效后重新登录。

| 环境变量          | 含义                     | 默认值                                |
| ----------------- | ------------------------ | ------------------------------------- |
| PORT              | 后端端口                 | 8090                                  |
| HOST              | 监听地址                 | 127.0.0.1                             |
| DATABASE_URL      | R2DBC 数据库地址         | 项目内 H2 文件库，见 application.yaml |
| DATABASE_PASSWORD | 数据库口令               | 空                                    |
| DEMO_DATA         | 初始化演示账号与文章     | true                                  |
| DEMO_PASSWORD     | 新建演示账号的口令       | Workbench2026!                        |
| COOKIE_SECURE     | Cookie 仅通过 HTTPS 发送 | false                                 |

部署时构建并运行 JAR，持久化数据目录；使用 HTTPS 时设置 `COOKIE_SECURE=true`。演示账号和示例文章用于本题开发与验收。

备份时先停止应用，再复制完整 `data` 目录。恢复时停止应用，用完整备份替换该目录后启动。初始化文章为合成数据，可按设计重新初始化；候选人交付后的业务数据须在重启后保留。

## 代码结构

```text
backend/
  src/main/java/dev/workbench/   接口、认证、业务服务、数据库访问
  src/main/resources/           配置、DDL、Thymeleaf 模板
  src/test/                     后端测试
ui/
  src/views/                    登录、列表、编辑
  src/components/               Vue 公共组件
  src/stores/                   Pinia 认证状态
  src/utils/                    日期工具
  tests/                        单元测试、浏览器测试
fixtures/article-analytics/   历史业务数据、数据字典和校验清单
gradle/wrapper/                 Gradle Wrapper
```

`ArticleService` 负责文章操作，`ArticleController` 提供接口，`PageController` 提供公开页面。数据库定义在 `backend/src/main/resources/schema.sql`，目前包含 users 和 articles 两张表。

### 现有接口

| 方法与路径                       | 用途                                 |
| -------------------------------- | ------------------------------------ |
| GET /api/health                  | 服务及数据库检查                     |
| GET /api/csrf                    | 获取写请求使用的 CSRF token          |
| GET /api/session                 | 当前账号                             |
| POST /api/session                | 账号口令登录                         |
| DELETE /api/session              | 退出                                 |
| GET /api/articles                | 按权限查询文章，支持 q、status、page |
| POST /api/articles               | 创建草稿                             |
| GET /api/articles/:id            | 读取文章                             |
| PUT /api/articles/:id            | 保存文章                             |
| POST /api/articles/:id/publish   | 发布                                 |
| POST /api/articles/:id/unpublish | 取消发布                             |
| GET /api/public/articles         | 公开列表                             |
| GET /api/public/articles/:id     | 公开详情                             |

写请求需要保留 Cookie，并携带 `GET /api/csrf` 返回的 headerName 和 token。登录参数为 username、password。创建与保存参数为 title、excerpt、body，长度上限分别为 200、500、50,000 字符。详情返回 `{ article }`，列表返回 `{ items, total, page, size }` 及分页信息。接口和数据结构可随业务实现调整。
